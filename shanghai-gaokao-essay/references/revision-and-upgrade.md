# 修改升格：诊断已有作文并局部升格

## 适用场景

用户提供了一篇已经写完的上海高考作文（自己写的、AI写的、或旧稿），要求"帮我看看这篇作文""怎么修改能提分""升格到一类卷""这篇作文哪里有问题"等。此时不走SKILL.md "从题目到成文"的新写流程，而是走本文件的诊断→定位→局部升格流程。核心原则：**先诊断，再决定动多大手术；能局部改的不整篇重写**——用户需要的是学到差距在哪，不是一篇被替换掉的新文章。

## R1 通读定档：给出粗略分数区间

先通读全文一遍，不做笔记，凭整体印象回答三个问题，据此给用户一个粗略档位判断（例如"当前大致在二类中55-58分区间，主要问题在立意深度和结构，语言问题较少"）：

1. 30秒读完首段，能否看出"审题准、观点明"？—— 决定是否已越过及格线进入二类。
2. 中间部分是观点集中，还是话题分散、平均用力？—— 决定二类上还是二类中。
3. 结尾是否让人觉得"收住了"，还是草草收尾或喊口号？

把这个粗略判断先告诉用户，再进入逐项诊断，让用户对升格空间有预期。

## R2 逐项诊断：套用九大通病表

把 SKILL.md《必须规避的九大AI写作通病》表当诊断清单，逐条过一遍原文，只列出**命中**的问题，并标注命中在第几段（或引用原文片段定位），不要对未命中的项目逐条说"这条没问题"。输出格式建议：

```
命中 #1 审题浅：第1段观点句未复现题干关键词"XX"，偏离了原问法
命中 #6 案例堆砌：第3段连续三个例子（A、B、C）均无阐释句，属于排例超限
（#7 引用幻觉：未发现杜撰引用，引用规范，未命中，不展开）
```

避免"结构可以更严谨"这类无法执行的泛泛评价，每条问题必须能让用户知道改哪一句、加哪一句。

## R3 立意与结构诊断：对照五段骨架找缺环

对照 references/structure-and-outline.md 的思辨五段骨架，检查原文缺了哪一环——这往往是二类卷冲一类卷的关键：

- 缺概念界定 → 大概率导致"审题浅"和"立论空泛"。
- 缺让步段 → 导致单向度赞美/批判，读起来武断，立场显得不够公允。
- 有深掘但没有异化/边界分析 → 停留在正面阐释，缺深度，是最常见的二类卷症状。
- 缺整合/升维段，直接从批判跳到结语 → 立意不能"落地"，显得虎头蛇尾。

对每一处缺失，指出**应插入在原文第几段之后**、大致写什么内容，并给出一两句起笔示范（而非空泛地要求"加一段深度分析"）。

## R4 语言与格式诊断

对照 references/language-and-style.md 和九大通病表第3、4、5、9条，检查：标题是否空泛俗套、是否有小标题/序号分点、首尾是否失衡（中间大两头小）、"然而/但是"是否超过3次、是否存在机械转折。这类问题通常**局部替换即可解决**，不需要动结构，给出具体的替换句示范而非只说"建议精简"。

## R5 输出形式：默认给诊断报告+局部修改建议，仅在必要时整篇重写

默认输出是"诊断报告 + 逐段可执行的修改建议/示范句"，不要自动把整篇作文重写一遍替换给用户——这样用户才能看清具体差距、学到方法，而不是拿到一篇看不出改动逻辑的新文章。

只有以下情况才整篇重写：

1. 用户明确要求"直接改好给我""帮我重新写一遍"；
2. 原文审题错误（跑题）或结构缺失过多（五段骨架缺3环以上），局部修改已不足以成立，必须推倒重来。

整篇重写时，仍要先完成R1-R4的诊断并简要呈现给用户（哪怕只有几行），再给出新稿，让用户理解"改在哪"，而不是凭空拿到一篇新文章。

## R6 分档目标与优先级：按"立意>结构>语言"权重排列修改顺序

明确告诉用户当前分档和目标分档之间差在哪一类问题上（立意/结构/语言），并按SKILL.md的权重"立意 > 结构 > 语言"排列修改优先级：先补立意深度和结构缺环，最后才抠语言细节。语言问题即使全部修好，若立意结构不动，也很难从二类中冲到一类下——这是本诊断流程中最容易被用户忽视、也最需要主动提醒的一点。

## 常见反模式（避免）

- 不要一上来就大段重写、绕过诊断——用户学不到东西，也可能改坏原本还不错的地方。
- 不要笼统评价（"语言不错，结构一般，加油"），必须具体到段落和句子。
- 不要用新的、原文未出现的例子替换掉原有例子，除非原例子确实存在事实错误或用错位置——优先"深化阐释"而不是"换例子"。
- 不要把"结构"和"语言"层面的小问题当成决定分档的主因——立意深度不够，语言再华丽也压不上一类。
